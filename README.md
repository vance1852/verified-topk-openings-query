# 岗位检索的多索引计划与完整排序

各记录目录保存独立的合成业务资料。SQL 文件仅包含原始关系表与已有行。manifest.json 记录库角色、表、行数及运行参数。timeline.json 记录后续客户端行为、来源提交或故障，用 pos 表示可比较的到达次序。同一 pos 按数组顺序。提交位置由相应记录的业务字段指定。

## 接入协议

本地坐标为整数网格，距离使用曼哈顿距离，次序为距小优先、工资高优先、岗位编号按字节序，重复地点以地点标识区分。要先用 shifts（资质及班）、states（报名人数和状态）检查同一岗位及地点，再取该岗位在请求里的最近合格地点。“最近地点”不等于“最近岗位”。positions 的 seen_at 指该行首次可见的业务断面。
模拟索引的 coverage 以轴对齐矩形给出四端点，左右及前后均闭合。index_rows 是可用命中的投影，coverage.through 表示范围能证实的最新来源位置。未覆盖部分或超出 through 的变更只能从还可用的基础事实得到证明。访问一条索引行或基础数据行分别计一个访问单位，读取范围声明和元数据不计；可选择规划方式。结果页和查找预算由请求指定。

## 本地资料

使用 Python 3.11.2 和内置 SQLite 3.40.1。以下命令从记录创建关系库，目标文件需要尚不存在。各角色可以作为独立 SQLite 文件读取。

~~~sh
python3 seed_db.py fixtures/near-misses-and-an-unindexed-site main-local.db --role main
~~~

使用 Python 的 sqlite3 打开新文件即可访问原始表。用 python3 -m unittest -v 核对资料可装载、表与原始记录一致、SQLite 可同时打开读写连接。后续事件保存在各自的原始记录中。
